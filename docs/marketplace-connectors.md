# Marketplace connectors and normalization

All connectors expose normalized rows and capability metadata: `supports_refresh`, `refresh_interval`, `requires_manual_update`. The current manual, JSON, CSV, URL-reference, user-pasted browser capture and fictional fixture workflows require manual updates. The approved-API capability reports not configured. No Facebook public API, authenticated browser session, automatic extraction or unrestricted data access is assumed. No scraping, anti-bot evasion or seller automation is implemented.

`MarketplaceSourceConnector` is the swappable boundary. JSON arrays and CSV exports feed the same `ListingInput`. Manual form submission uses the same pipeline. Browser capture is explicitly user-provided fields using the normalized import format. URL references are HTTP(S) only and never fetched by the backend; completion requires manual title, asking price and other required fields.

Identity is `(source, source_listing_id)`. Existing source/ID pairs update observations instead of creating new items. Updates older than the last observation are rejected. Distinct IDs can still be linked as reposts. Optional attributes stay nullable: missing rating/distance/comps do not become zero. Publication time is distinct from first observation. Currency is restricted to USD; monetary inputs use Decimal, timestamps must include timezone, coordinate pairs must be complete. Metadata has bounded allowed shapes, HTML is stripped, URLs reject embedded credentials and unsafe schemes.

Imports accept at most 100 rows / 1 MB; each normalized record is bounded to 64 KB. Per-row savepoints allow partial success and report invalid rows. Dry run rolls back listing/evidence/history/analysis/event writes. HTTP bodies are bounded before parsing and require trusted Origin plus enabled local writes. JSON/CSV parse failures return validation errors rather than pretending success. No remote connector can currently fail mid-network fetch because none performs network acquisition.

CSV uses scalar columns plus JSON-encoded complex fields such as `comps`, `demand`, `item_metadata`, `image_metadata`. See [CSV](examples/marketplace-listings.csv) and [JSON](examples/marketplace-listings.json) templates. Supply `source_url` for attribution and explicit source labels on comparable/cohort evidence. Do not import cookies, tokens, contact databases or private session material. Photo URLs are not automatically fetched; the user must request loading supplied photos in the detail view.
